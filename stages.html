Stage 1 — Single-player world

A player can comfortably walk around a small 2D world.

Delivered

  • Pure Canvas 2D rendering — no game library, no external dependencies
  • World: 3840 × 2880 px (120 × 90 tiles at 32 px each)
  • Player avatar — glowing blue-white orb with radial glow effect
  • WASD + arrow key movement with diagonal normalisation
  • Camera that follows the player, clamped to world bounds
  • Collision: player cannot leave the world rectangle
  • Five interaction zone stubs — golden glowing circles, "Press E" prompt when near
  • DPR-aware canvas sizing (crisp on Retina/HiDPI screens)
  • Deterministic procedural star field — consistent as camera moves
  • 19 unit tests for all pure game logic functions

Module structure

apps/web/src/game/
  constants.ts   world size, speed, radii
  types.ts       GameState, PlayerState, Camera, InteractionZone
  input.ts       InputHandler — keyboard, diagonal normalisation
  physics.ts     movePlayer, computeCamera, detectNearbyZone, tick (pure)
  renderer.ts    Canvas 2D — stars, grid, glow, zones, HUD
  engine.ts      GameEngine — owns loop, input, state, renderer

apps/web/src/
  hooks/useGame.ts          React hook — lifecycle + resize
  components/GameCanvas.tsx 'use client' canvas mount point

Key design decision

All movement, collision, and camera logic lives in physics.ts as pure functions — no DOM, no React, no Canvas. This makes them trivially testable and keeps them ready to accept server-authoritative positions in Stage 2 without rewriting the rendering layer.

Success criterion — met

A single player can walk around a 3840 × 2880 world with smooth 60 fps movement and camera follow. 19/19 physics tests pass.

Stage 2 — Realtime multiplayer

Multiple clients share the same world in real time.

Delivered

  • Socket.IO connection lifecycle — join, leave, reconnect with auto-resume
  • Server-authoritative player positions via WorldState (in-memory)
  • Movement broadcasting — Player A moves, all other clients see player:moved
  • World snapshot on connect — joining client receives all current players
  • Client-side position interpolation (lerp at 12 Hz → smooth remote movement)
  • Session token stored in localStorage — persists across page refreshes
  • Remote players rendered as lavender orbs (distinct from local blue-white)
  • HUD shows live player count
  • Server validates movement magnitude (rejects teleport attempts)
  • 15 new server tests (18 WorldState unit + 8 multiplayer socket integration) + 19 existing physics tests = 53 total

New files

apps/game-server/src/game/
  constants.ts     PLAYER_SPEED, MAP dimensions, MAX_DT
  worldState.ts    WorldState — in-memory authoritative player map

apps/web/src/game/
  network.ts       NetworkClient — Socket.IO client, session token, sendMove

Protocol change

PlayerMovePayload changed from cardinal direction enum to {dx, dy, dt, sequence} — continuous normalised vector + frame delta, matching the client physics model. Server clamps dt ≤ MAX_DT and rejects moves where √(dx²+dy²) > 1.

Success criterion — met

Multiple browser tabs connect to the same server. Each can move. All see each other's movement in real time. 53/53 tests pass.

Stage 3 — Meteor vertical slice

The complete core emotional loop works end to end.

Delivered

  • Meteor creation form — category selector (Burden / Moment / Hope / Gratitude) + 280-character text input with live counter
  • Server-side safety classifier — keyword-based blocklist gates high_risk content before DB write; sensitive content passes with metadata
  • Meteor persisted to PostgreSQL (meteors table) and broadcast to all connected clients via meteor:created
  • Interaction zone detection — player walks near a meteor glow, press E to read it
  • Meteor read form — shows category, anonymous content, five predefined responses
  • Server validates: owner cannot acknowledge own meteor; one resonance per player per meteor (DB unique constraint)
  • Meteor → Star transition: meteor:acknowledged + star:created broadcast to all clients simultaneously
  • Writer receives private notification:heard — "Someone heard you." toast
  • Acknowledger receives light:earned — ✦ 1 Light HUD counter
  • All state (meteors, stars) persists across refresh / reconnect — loaded on world:snapshot
  • Five interaction zones repositioned to be immediately visible from spawn
  • Session identity switched to sessionStorage so each browser tab is an independent player
  • New DB migration: users.session_token (unique), players.user_id unique constraint
  • 66 tests passing — 47 server (WorldState, multiplayer, classifier, meteor lifecycle) + 19 web (physics)
